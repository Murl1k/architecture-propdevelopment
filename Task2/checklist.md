# проверочный лист для бизнес-систем PropDevelopment

## системы и их работа с данными

| домен | системы | данные и характер работы | что важно для безопасности |
| ----- | ------- | ------------------------ | -------------------------- |
| продажи | витрина продаж (javascript, react) | подбор и бронирование, клиент указывает фио, телефон, почту, может заполнить расширенную форму | вход для клиентов через firewall, rest к приложениям продаж |
| продажи | client-mart-estate-app, client-mart-estate-db | данные о недвижимости | передача сырых данных в хранилище по cdc |
| продажи | client-mart-app, client-mart-db | онлайн-сделка, данные расширенной формы | интеграция с госорганами через смэв (soap), юридически значимый процесс |
| продажи | client-tour-app, client-tour-db | онлайн-тур по объекту | результаты осмотра фиксируются в системах |
| продажи | client-crm-app, crm-db | клиентские данные, регистрация клиента, карточка и профиль по rest | одна из нескольких точек регистрации, менеджеры входят через active directory |
| жку | витрина сервисов для собственников (мобильное приложение ios, android) | оплата жку, информация от управляющей компании, ремонт, умный дом | вход для собственников через firewall, управление замком квартиры |
| жку | tenant-core-app, tenant-core-db | услуги жку для собственников | связан с внешними системами: поставщик ресурсов жкх и платежная система |
| жку | crm, crm-tenant-db | данные собственников | передача сырых данных в хранилище по cdc |
| партнеры | системы управляющих компаний | оплата жку и информация о доме для собственников | api без единых политик безопасности и без системного контроля данных |
| аутентификация | auth-service-1 (keycloak), auth-db-1 | регистрация и аутентификация покупателей | к нему идут связи от обеих витрин, у связи от витрины продаж подпись регистрация, аутентификация [rest], точка регистрации клиента наряду с client-crm-app |
| финансы | accountant-service-1 (keycloak), auth-db-1, active directory | бухгалтерский учет | у связи accountant-service-1 с active directory подпись аутентификация |
| данные | хранилище данных (greenplum), dwh хранилище (s3), bi, отчетность | единое хранилище данных для всех систем компании, сырые данные приходят по cdc | бизнес-аналитик аутентифицируется через active directory, аналитик bi работает с хранилищем, планы на bi, ml и ai |

- инфраструктура: свои серверы, свой цод, приватное облако и арендованные облачные мощности, для временного расширения мощностей на этапах доработки и тестирования команды могут использовать облачные ресурсы и управляемые сервисы
- резервное копирование есть для всех баз данных
- специалист по ИБ один на компанию

## выбор разделов

### I. управление доступом: включен целиком

- проблема компании в доступе: системы обработки данных не ограничивают доступ, партнер одной управляющей компании видит данные другой, в личном кабинете появляются чужие данные
- вопросы про минимальные привилегии, единый реестр учетных записей и централизованный контроль нужны из-за разрозненных систем входа: auth-service-1 и accountant-service-1 на keycloak, две службы active directory
- вопросы про mfa и пароли остаются: в системы входят менеджеры, аналитики и бухгалтеры, а в базах персональные данные клиентов и собственников
- вопрос 7 про атрибуты ближе всего к проблеме с партнерами: доступ партнера надо привязывать к его управляющей компании
- вопрос 9 про замкнутые контуры нужен для crm и хранилища, где лежат персональные данные

### II. безопасность данных: включен целиком

- главные приоритеты здесь: классификация данных, учет персональных данных, контроль потоков
- планы на bi, ml и ai упираются в управление и хранение потоков данных, поэтому остаются вопросы про data governance, целостность и анонимизацию
- в хранилище сходятся данные разных систем компании
- резервное копирование всех баз в описании есть, но про защищенное хранение копий и проверку восстановления ничего не сказано, это выяснит аудит
- вопросы про ключи и уничтожение данных нужны при гибридной инфраструктуре с арендованными мощностями

### III. защита инфраструктуры: включен частично, 10 вопросов из 12

- firewall в описании стоит только перед клиентами и собственниками, поэтому остаются вопросы про сегментацию, фильтрацию между сегментами и контроль периметра
- вопросы про ids, ips и мониторинг трафика остаются из-за партнерского api и интеграции со смэв
- сканирование облачных инфраструктур остается из-за арендованных мощностей и временных облачных ресурсов
- из шаблона убраны вопросы про антивирусы, edr и обновление сигнатур: проблемы компании в доступе и потоках данных, про рабочие станции в описании ничего нет

### IV. управление инцидентами: включен целиком

- руководство обеспокоено утечкой у конкурента, аудит должен помочь не допустить такого у себя
- специалист по ИБ один, решения и изменения доходят до него не все: вопросы про план реагирования, оповещения и эскалацию проверяют, кто вообще узнает об инциденте
- вопрос про частоту аудитов остается, компания готовится к комплексному аудиту

### V.1. общие вопросы: включен частично, 2 вопроса из 4

- оставлены vpn и резервное копирование в облаке: команды работают с приватным облаком и арендованными мощностями, удаленный доступ к ним и копии баз надо проверить
- вопросы про mdm и неавторизованные устройства убраны: в описании мобильное приложение только для собственников, про корпоративные мобильные устройства в описании ничего нет

### V.2. оборудование и физическая безопасность: включен целиком

- у компании свой цод и свои серверы, где работает большинство продуктов

### VI. внешние интеграции и соответствие законодательству: добавлен

- шаблон не покрывает api партнеров и контроль данных во внешних интеграциях, это одна из двух главных проблем компании
- шаблон не покрывает соответствие законодательству РФ, в нем один вопрос про актуализацию классификации, а компания не уверена в соответствии своих процессов
- api партнеров: вопросы про единые политики, разграничение данных между управляющими компаниями и персональные данные в контрактах
- контроль данных: вопросы про потоки между продуктами и во внешние системы, несколько точек регистрации клиента, чужие данные в личном кабинете
- вопрос про соответствие 152-ФЗ и вопрос про передачу специалисту по ИБ информации об изменениях: без нее он не видит новые интеграции
