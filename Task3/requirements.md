# требования к внешним интеграциям умного дома

## требования к безопасности

1. изображение лица считается биометрическими персональными данными, номер автомобиля вместе с квартирой тоже персональные данные (152-ФЗ); в tenant-smart-home-db лежат идентификатор жильца, номера автомобилей, квартира и срок разрешения, изображений лиц и видео там нет
2. лицо регистрируется только после письменного согласия самого жильца на обработку биометрии; согласие и его отзыв записываются в tenant-smart-home-db, при отзыве данные жильца удаляются у нас, а платформе уходит запрос на их удаление
3. платформа получает от нас только изображение лица и идентификатор жильца при регистрации, запрос на удаление данных жильца и команды открытия; фио, телефон, квартира, номера автомобилей и управляющая компания не передаются, идентификатор жильца случайный и не выводится из персональных данных
4. договор с партнером фиксирует хранение биометрических данных в дата-центрах на территории РФ, срок хранения, удаление по запросу и запрет передачи третьим лицам; видео звонка не записывается ни у нас, ни у партнера
5. обмен мобильного приложения собственника (на диаграмме Витрина сервисов для собственников) с системами PropDevelopment и обмен partner-api-gateway с платформой умного дома идут только по tls; номера автомобилей и привязки жильцов к квартирам хранятся в tenant-smart-home-db в зашифрованном виде
6. журнал в tenant-smart-home-db фиксирует каждое открытие и каждое изменение разрешения: кто, какое устройство, способ (распознавание, звонок, команда собственника), время, результат; в логах нет изображений и видео, номера автомобилей маскируются
7. автоматически дверь подъезда и шлагбаум открываются только при распознавании и действующем разрешении; открытие по звонку и вручную идет только по команде собственника из мобильного приложения после проверки его прав, в остальных случаях команда не отправляется

## протоколы аутентификации и авторизации

1. собственник входит в мобильное приложение через auth-service-1 (keycloak) по openid connect; в tenant-smart-home-app приложение передает access token (jwt) с идентификатором собственника и ролями, срок действия токена ограничен
2. роли по rbac берутся из токена: роль собственника дает доступ к управлению своими разрешениями и к открытию двери подъезда и шлагбаума; доступ к конкретному объекту проверяется по abac: квартиру и жилой комплекс собственника tenant-smart-home-app получает из CRM по rest и сверяет с данными устройства и разрешения в tenant-smart-home-db
3. partner-api-gateway и платформа умного дома аутентифицируют друг друга по сертификатам (mtls), сертификаты чужих издателей отклоняются
4. запросы платформы к partner-api-gateway авторизуются по токену oauth 2.0 с ограниченным сроком действия и набором прав (scope)
5. доступ партнера ограничен жилыми комплексами, где стоят его устройства, tenant-smart-home-app проверяет это по abac; так в новой интеграции не повторяется проблема из описания компании, когда партнер одной управляющей компании видит и меняет данные другой

## взаимодействие с внешней платформой

1. весь обмен с платформой умного дома идет через partner-api-gateway: к платформе обращается только он, изнутри к нему обращается только tenant-smart-home-app, снаружи только платформа; единые политики безопасности (аутентификация, контроль состава передаваемых данных) применяются в нем
2. в контракт api включаются только поля, нужные для двух услуг, состав контракта и его изменения согласуются со специалистом по ИБ до выпуска; partner-api-gateway пропускает только пути и методы из контракта, запросы и ответы с полями вне контракта отклоняет
3. от нас к платформе по rest идут команды открытия (идентификатор устройства и тип: дверь подъезда или шлагбаум), регистрация лица жильца (изображение лица и идентификатор жильца) и запрос на удаление данных жильца, канал защищен mtls
4. от платформы к нам идут события по rest и видео звонка по ws, канал защищен mtls; в событии звонка: идентификатор устройства и квартира, в которую звонят; в событии распознавания лица: идентификатор устройства и идентификатор жильца; в событии распознавания номера: идентификатор устройства и номер автомобиля
5. решение об открытии по распознаванию принимает tenant-smart-home-app: проверяет разрешение в tenant-smart-home-db и только после этого отправляет команду, платформа сама дверь подъезда и шлагбаум не открывает
6. при звонке tenant-smart-home-app по квартире находит собственника в CRM и отправляет уведомление в мобильное приложение по ws, видео идет от платформы через partner-api-gateway; открыть дверь подъезда или шлагбаум собственник просит из мобильного приложения по rest, команда уходит платформе через partner-api-gateway
